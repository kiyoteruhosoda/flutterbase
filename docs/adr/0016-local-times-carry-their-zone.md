# 0016. 画面の時刻には時間帯を付け、時刻を文字にするのは 1 か所にする

- 状態: 採用
- 日付: 2026-11-05
- 関係するもの: fastapitemplate ADR-0105（同じ決まりの Web 側）、noticeapp（先に入れた派生アプリ）

## 文脈

時刻は内部では UTC で持ち、画面で端末の時間帯に直す（CLAUDE.md 基本方針 8）。直した時刻には、
それがどの時間帯の時刻かが書かれていなかった。画面で見るだけなら困らないが、コピーして
チャットや課題へ貼ると `07:00` が日本の時刻か UTC かが分からない。派生アプリ noticeapp では、
UTC で動いているホストの知らせを貼ったときに取り違えが起きかけた。

時刻を文字にする箇所はお知らせ・メンテナンス画面・見本の詳細画面に散らばっていて、1 か所を
直しても新しく足した画面で同じことが起きる。

## 決定

1. 端末の時間帯に直した時刻の後ろには、時間帯を `UTC+9` の形で付ける。分があれば `UTC+5:30`、
   ずれが無ければ `UTC`。夏時間はその時刻の日のずれで書く。
2. 時刻を文字にするのは `lib/presentation/formatting/local_time.dart` の `formatLocalDateTime`
   だけにする。日付の長さは `LocalDateLength`（short / medium / full）で選ぶ。
3. `tool/check_architecture.dart` の規則 `local-time-format` が、そのファイルの外で
   `toLocal()` と `formatTimeOfDay()` を呼ぶ箇所を落とす（CI の `architecture` の段）。

## 理由

- 時間帯は略称（`JST`）ではなく数字で書く。略称は端末ごとに出たり出なかったりし、同じ略称が
  複数の時間帯を指すこともある。数字なら端末に依らず同じに出る。
- 「付ける」と書いておくだけでは新しい画面で付け忘れる。書き方を 1 か所に寄せ、ほかを機械で
  止めれば付け忘れは CI で落ちる。既存の設計の検査（`check_architecture.dart`）は文字列でなく
  構文で見るので、コメントや文字列の中の `toLocal` には反応しない。
- 止めるのは「端末の時刻に直す」入口（`toLocal`）と時刻の書式（`formatTimeOfDay`）だけにした。
  日付だけの書式（`formatShortDate` など）は時刻を含まず、時間帯の取り違えが起きにくいので止めない。

## 影響

- 時刻の表示が少し長くなる（後ろに ` UTC+9` が付く）。
- 派生アプリは、この更新を取り込むと自前の画面の時刻が `local-time-format` で落ちる。
  `formatLocalDateTime` へ置き換える。
- 試験のファイル（test/）は対象外。期待値を作るのに `toLocal()` を使ってよい。
