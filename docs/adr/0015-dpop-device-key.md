# 0015. assay のトークンを、アプリごとの Keystore の鍵に DPoP で結び付ける

- 状態: 採用
- 日付: 2026-11-04
- 関係するもの: [0007](0007-optional-assay-sign-in.md)、assay（idp）ADR-0075（トークンの口の DPoP）、
  fastapitemplate ADR-0103（アプリ向けの口が証明を確かめる）、task #893（親 #875）

## 文脈

アプリは assay のリフレッシュトークン（30 日）を secure storage に、アクセストークン（300 秒）をメモリに持つ。
どちらも持っているだけで使える（Bearer）ので、バックアップ・root 化した端末・ログへの書き出しなどで外へ出ると、
別の端末からそのまま使われる。assay は DPoP（RFC 9449）に対応した。持ち主の了承（11/04）: 鍵は各アプリが持つ。

## 決定

1. **鍵はアプリごとに Android Keystore で作る**（`MainActivity` の `nolumia/dpop_key` チャンネル）。P-256・署名だけ・
   取り出せない。StrongBox があればそこに作る。毎回の指紋は求めない（呼ぶたびに署名するため）。別名は `dpop`。
   Keystore はアプリごとに分かれているので、ほかのアプリからは使えない。
2. **呼ぶたびに証明を作る**（`DpopProofSigner`）。`typ` は `dpop+jwt`、`alg` は ES256、`jwk` は公開鍵、中身は
   `jti`（乱数）・`htm`・`htu`（問い合わせと断片を外した URL）・`iat`・リソースへは `ath`。Keystore の署名（DER）は
   JOSE の `r || s` に直す。nonce は使わない（assay の ADR-0075 決定 3）。
3. **トークンの口（`authorization_code`・`refresh_token`）に証明を付ける。** assay が `token_type: DPoP` で返したら
   結び付いた印で、Web アプリを呼ぶときは `Authorization: DPoP <token>`・`DPoP: <証明>`・`X-ID-Token: <ID トークン>`
   を付ける（ID トークンは Web アプリが初めて来た人のプロフィールを読むため。fastapitemplate ADR-0103 決定 5）。
   `Bearer` で返ったら今までどおり。
4. **時計は応答の `Date` で直す**（`ServerClock`）。assay と Web アプリは `iat` を 120 秒前〜60 秒後しか受けない。
   5 秒を超えてずれていれば、そのずれを証明の時刻に足す。トークンの口が `invalid_dpop_proof` を返したら、1 回だけ
   証明を作り直す。2 回目も断られたら、後でやり直す失敗（サインアウトはしない）。
5. **Keystore が使えない端末では証明を作らない**（今までどおり Bearer）。結び付いた後に鍵が使えなくなったら、
   Web アプリへの呼び出しは失敗として返す（鍵なしでは送れない）。
6. **サインアウトで鍵を消す。** 次のサインインは新しい鍵に結び付く。

## 理由

- **アプリごとの鍵**: Keystore の鍵はそれを作ったアプリからしか使えない。認証用のアプリにまとめると、呼ぶたびに
  アプリ間の呼び出しが要る（#875 設計書 第 1 版 3.5）。
- **毎回の指紋を求めない**: アクセストークンは 300 秒で、Web アプリへの呼び出しごとに署名する。指紋を毎回求めると
  使えない。鍵を取り出せないことと、トークンが端末の外で使えないことが守り。
- **時計を直す**: 端末の時計が数分ずれていると、すべての呼び出しが断られる。nonce の往復を足すより安い。

## 影響

- ⚠ **対の Web アプリが fastapitemplate ADR-0103 を取り込む前に、この版のアプリを配らない。** 古い Web アプリは
  `Authorization: DPoP` を読めず、アプリの呼び出しがすべて 401 になる。assay が古い（DPoP 無し）場合は Bearer で
  返るので、そのまま動く。
- 今ログインしているアプリは、この版へ更新した後の最初の更新でその鍵に結び付く（ログインし直さなくてよい。assay の
  ADR-0075 決定 7）。
- 防げないこと: 端末そのものを乗っ取られた場合（端末の中から鍵で署名できる）。
