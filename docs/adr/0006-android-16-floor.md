# 0006. 対象を Android 16 (API 36) 以上に限る

- 状態: 採用
- 日付: 2026-08-30

## 文脈

`android/app/build.gradle` は次の値になっています。

```groovy
compileSdk = 36
minSdk     = 36
targetSdk  = 36
```

`minSdk = 36` は **Android 16 以上の端末にしか入らない**という意味です。ところが
この値の根拠はどこにも書かれていません。3 つが同じ数字なので、**`compileSdk` を
書き写した事故に見えます。** 実際 2026-08-30、別件（配布物のサイズ削減）の調査中に
「これは取り違えではないか」と疑われました。数字だけを見て第三者が同じ疑いを持つ
状態が続くと、いつか根拠のないまま下げられます。

下限の設定が厄介なのは、**外したときの失敗が何も説明してくれない**ことです。
端末が下限を下回ると、インストールは「アプリをインストールできませんでした」と
出て終わります。理由は画面に出ず、`adb` でログを取れる環境がなければ切り分けが
できません。同じ 2026-08-30 に photonestapp で「最新版が入らない」という申告があり
（そちらの原因は端末の空き容量でしたが）、症状はこれと区別が付きませんでした。
配布相手が手元にいない以上、**下限は「決めて書いてある」状態でなければ運用できません。**

なお、下げる判断の前例はあります。`photonestapp` だけは `minSdk = 31` です。
App Link の intent-filter で `android:pathAdvancedPattern`（API 31+）を使う必要が
あり、その根拠は `build.gradle` のコメントに書いてあります。**下げること自体を
禁じているのではなく、根拠を残さずに動かすことを禁じます。**

## 決定

**`minSdk = 36` を維持します。この雛形から作るアプリは、既定で Android 16 以上の
端末だけを対象にします。**

- この値は事故ではなく意図した下限であることを、この ADR で明示します
- 古い Android のための互換分岐を書かない・テストしないことを、設計の前提に置きます
- **下げる必要が出たアプリは個別に判断し、根拠をその場に残します**
  （`build.gradle` のコメント、または当該リポジトリの ADR）。`photonestapp` の
  `minSdk = 31` がその形です
- 下限を動かすときは、**下限に依存している記述を同時に見直します。** 具体的には
  マニフェストで使っている API 31+ の属性、権限の `maxSdkVersion` 分岐、
  「この API は最低 SDK で常に使える」という前提で書いたコードです

## 結果

- 分岐が要る新しい API を素で使えます。互換ライブラリとテスト対象が増えません
- **端末が下限を下回ると、理由の出ないインストール失敗になります。** 配布する前に
  相手の Android バージョンを確認できる状態にしておく必要があります
- 配布面（`dl.nolumia.com` / `share.nolumia.com`）は APK を置くだけで、この条件を
  画面に出しません。**配布時の連絡に「Android 16 以上」と明記します**
- アプリごとの下限は `HANDOVER.md` §9-F にも一覧で書いてあります
